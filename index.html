Decision 01 — Rebuild vs Migrate

Challenged the company's assumption before writing a single line of code

When I joined, the plan was to take the existing DOB portal (built in Angular 12) and migrate it to Angular 17 — rename things, upgrade versions, ship. I did a full migration analysis first. The blockers were serious: Angular requires step-by-step migration (12 → 13 → 14 → 15 → 16 → 17), Bootstrap had breaking class-level changes across those versions, and PrimeNG hadn't updated their version at the time. Beyond the libraries, the codebase itself had no proper file structure — the architecture was complex and dirty. My estimate: 7–8 months minimum, with a real risk of being blocked at any step. The production deadline was 4–5 months.

I recommended rebuilding from scratch in Angular 17. I built a working prototype solo — User Management, full Auth flow, and the first Compliance screen — and presented it to the board alongside a written migration analysis. The board approved the rebuild on the spot. That single decision saved the project an estimated 3–4 months and removed all inherited technical debt.

Decision 02 — Standalone Components over NgModules

Pushed for the newer Angular paradigm against initial resistance

I proposed adopting Angular's Standalone Component strategy from day one instead of the traditional NgModule approach. There was pushback. Rather than arguing in the abstract, I built a side-by-side comparison in the dev environment and showed the concrete difference in bundle size and code structure. The evidence made the case. Standalone components became the standard for the entire product — cleaner architecture, better performance, smaller bundles, and a codebase significantly easier to onboard new engineers into.

Decision 03 — NgRx State over localStorage

Caught a compliance security risk and redesigned the data layer around it

While reviewing the DOB codebase, I found that tokens and user data were being persisted in localStorage. In a fintech product operating under State Bank of Pakistan regulations, this was a significant security compliance risk. I raised it with management, walked through the threat surface, and proposed a solution: move all sensitive state into an NgRx in-memory store, with HTTP Interceptors handling token attachment, refresh, and error propagation at the transport layer. This became the foundation of the entire state architecture — security-first by design, not retrofitted.

Outcome — Validated by the Market

Months after launch, YAP Pakistan entered the State Bank pilot phase. The regulator's compliance requirements included running on the latest versions of all technology across every product — mobile, admin, and backend. Because the portal was built on Angular 17 from scratch and we'd been migrating continuously alongside every release, we were already compliant. A team that had gone the migration route would have shipped on Angular 13 or 14 — and been forced into an emergency upgrade under regulatory pressure. The rebuild decision saved the product twice: once at the start, and once when the regulator asked. We're currently on Angular 20 and planning the v21 migration.

Performance Fix — NgRx Pub/Sub

As the platform grew, shared data like user details and application lists was being fetched via API on every component that needed it — no caching, no shared state. Pages slowed down, load times compounded, and the network was saturated with duplicate calls. The team adopted NgRx with a Publisher/Subscriber architecture: fetch once, store in state, subscribe anywhere. Redundant API calls eliminated, load times reduced significantly across the platform.

Full Stack Delivery — Dashboard to DB

Built complete features end-to-end across the stack — Angular frontend through Java/Hibernate REST APIs down to MySQL with stored procedures. The Dashboard module was a full-stack solo delivery: UI components, API layer, data queries, and stored procedures for complex loan data reporting. Also owned modules including Point of Sale, Loan Assessment, Settlement Management, and Contract Modification.

Finance Calculation Utility

The Finance Management module required complex payment calculations that were being duplicated across multiple areas of the platform. Built a centralised calculation utility that could be imported and reused across any module needing financial logic — reducing code duplication, ensuring consistency, and making future calculation changes a single-point update rather than a platform-wide find-and-replace.

Angular Strict Mode & Version Migrations

Executed Angular version migrations across both platforms — from Angular 8 through to Angular 16 — with zero production downtime. Introduced TypeScript strict mode (available as default from Angular 15) across the codebase, catching a class of type-safety bugs at compile time that had previously surfaced only in production. Each migration improved platform stability and kept the codebase aligned with modern Angular patterns.
